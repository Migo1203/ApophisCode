# ApophisCode 新媒体增长与市场研究

本项目面向 ApophisCode 的中国大陆市场，目标是在真实产品研究和数据验证的基础上，逐步建立可执行的新媒体获客体系，关注注册、首次 API 调用和付费等环节。

项目负责人提供的官网是 [https://apophis.uk/](https://apophis.uk/)。初查时非 `www` 地址在本环境受阻；复查已读取 `www` 官网的公开配置和模型广场。产品公开声明与实际使用能力需区分，服务地区、具体接入和账单等仍待验证。研究成果待负责人审核。

## 如何使用

1. 从 [当前任务](tasks/当前任务.md) 和 [路线图](项目路线图.md)了解状态与下一步。阶段顺序用于组织工作，具体范围和优先级由项目负责人决定。
2. 研究时复制 [产品分析](templates/产品分析模板.md)、[竞品分析](templates/竞品分析模板.md)、[内容分析](templates/内容分析模板.md)或[运营复盘](templates/运营复盘模板.md)模板，按实际需要保存到 `research/`；经核实且适合复用的结论再整理到 `docs/`。
3. 在 [来源索引](research/来源索引.md)登记证据，记录链接、核查日期和适用范围；在 [问题与决策](tasks/问题与决策.md)记录未解决问题和负责人作出的关键决定。
4. 对外发布、重要定位和敏感商业决策交由项目负责人最终决定。任何未经证实的信息都不得作为产品事实或宣传承诺。

Phase 1 的公开资料初查见 [产品研究记录](research/产品研究-2026-10-29.md) 和 [通用产品知识](docs/产品知识.md)。新发现见 [官网与使用流程补充](research/官网与使用流程补充-2026-10-29.md)；实际操作仍待验证，先由负责人审核。真实账号操作、实际调用和费用支出需先明确授权、范围与预算。

## 协作与数据安全

默认使用简体中文，技术名称保留英文。事实、推断、假设与建议分开标记；无法核验的内容标为「待验证」。不得在仓库中保存真实 API Key、密码、客户个人信息或其他敏感数据。`.gitignore` 只能减少误提交，不能替代提交前检查。

下一阶段需要的资料见 [待提供的产品资料](tasks/待提供资料.md)。本仓库保存研究框架与经过处理的证据，不要求提交账号凭据或原始客户数据。
