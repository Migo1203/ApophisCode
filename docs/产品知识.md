## 基础概念

| 名词 | 通俗解释 |
| --- | --- |
| 模型 | 接收输入并生成输出的 AI 系统；不同模型及版本的能力、速度、输入类型和费用可能不同。模型 ID 是接口中识别模型的名称，不等于能力保证。 |
| API | 软件之间约定好的请求和响应方式。好比应用向服务窗口提交任务、接收结果；服务可能返回错误。API 与网页聊天都是使用 AI 的方式，账号、权限和计费未必相通。 |
| API Key | 软件调用接口时用于识别和授权的秘密凭据，类似钥匙。泄露可能造成他人使用额度或访问数据。只放在可信的密钥管理方式中；不要放进代码仓库、截图、聊天、日志或浏览器前端。泄露时按平台方式立即撤销并检查用量。 |
| Base URL | 客户端发送 API 请求的基础地址；软件会按协议拼接具体路径。网址首页不一定就是 API 地址；是否需要 `/v1` 等取决于平台和客户端。以提供方对具体工具的说明为准。 |
| Token | 文本被模型处理时使用的片段单位，可能是字、词的一部分或标点；不同语言和模型的切分不同，不能按中文字符数固定换算。输入、输出、缓存及部分模型的推理 Token 可能分别统计或计费 [S-005](../research/来源索引.md#s-005)。这里的 Token 与用于认证的令牌不是同一概念。 |
| 上下文窗口 | 模型一次处理内容的容量限制，通常按 Token 计算。对话历史、系统指令、用户输入、工具结果和生成内容可能共同占用；具体计算依接口和模型而异。 |
| API 中转／代理 | 客户端先把请求发送给中间服务，再由其路由或转换后向上游发送，结果经中间服务返回。数据会经过中间服务，需核对权限、条款和数据处理；中转不自动说明官方授权、质量或模型真实性。 |
| API 聚合 | 一个入口整合多个模型或提供方的访问、账户或计费等能力。具体整合程度取决于服务；统一接口不保证所有模型、工具调用或流式行为都兼容。中转与聚合可能重叠，但不是同义词。 |
| 接口兼容 | 接口路径、认证、请求／响应格式以及流式、工具调用等行为符合客户端需要。仅声称“OpenAI 兼容”不能证明支持每个 OpenAI API 或所有功能。 |

## 模型计费：怎么估算

按 Token 的常见计算方式是：**输入 Token 数 ÷ 计价单位 × 输入单价 + 输出 Token 数 ÷ 计价单位 × 输出单价**，另加适用的缓存、多模态、工具或服务费用。输入和输出通常有不同价格；对话历史可能反复作为输入发送。实际计费规则、税费、折扣、最低费用及是否有其他项目以平台价目表和账单为准。OpenAI 公开价格列出输入、输出和缓存等不同项目，仅作通用例子 [S-006](../research/来源索引.md#s-006)。

**虚构算例，不是产品报价**：假设输入每 100 万 Token 为 2 元、输出每 100 万 Token 为 8 元，某次使用 1,000 输入 Token 和 500 输出 Token，且没有其他费用，则估算为 0.002 + 0.004 = **0.006 元**。不同模型、缓存或收费单位会改变结果；实际账单才是核对依据。

## 通用首次调用流程

先核对条款、隐私、价格和预算 → 根据提供方指引注册或登录 → 确认可用额度 → 安全创建密钥 → 获取官方 Base URL、协议和模型 ID → 配置可信客户端 → 发送不含敏感信息的短测试 → 检查回复、用量和费用 → 按需撤销测试密钥。具体步骤、按钮与软件配置见 [研究记录中的逐步表](../research/产品研究-2026-10-29.md#从注册到首次调用通用框架尚非产品实测教程)。

**官网配置列出的 API 基础地址为 `https://www.apophis.uk`，但具体接口路径、客户端配置、账号权限和实际调用尚未验证；本次没有发起调用。** 模型广场公开列出模型及计费模式，最终费用和模型可用性需核实；不要从主页或第三方检测地址猜测接口路径。服务地区、客户类型与数据处理条款尚有待澄清，详见 [官网补充研究](../research/官网与使用流程补充-2026-10-29.md)。Codex CLI、Claude Code 和 Cherry Studio 各需核对版本、接口格式和模型能力，见 [接入条件](../research/产品研究-2026-10-29.md#工具接入分别核验)。

## 如何理解平台价值

开发者可能希望把模型接入软件，工具使用者可能希望在一个界面切换模型，团队可能希望集中管理权限和费用。若服务具备相应能力，可能减少接入或管理工作，但效果取决于模型、兼容性、价格、隐私和服务条件。这些只是用户需求假设，尚未证明 ApophisCode 的目标用户及优势。关于收费方式、需要询问负责人什么，以及未来适合讲解的知识点，见 [产品研究](../research/产品研究-2026-10-29.md)。
